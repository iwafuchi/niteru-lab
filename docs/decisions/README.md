# 設計の判断の記録

設計や技術選定で判断したことを、1 件 1 ファイルで残します（ADR：Architecture Decision Record の形式）。
コミットメッセージは変更ごとの理由を、ここは後の工程でも参照し続ける判断を扱います。

## 書き方

- ファイル名は `NNNN-<内容>.md`（例：`0001-input-validation.md`）。番号は連番
- 一度書いた記録は基本的に書き換えない。判断が変わったら新しい記録を追加し、古い記録の状態を「置き換え済み（NNNN）」にする
- 次の見出しで書く

```markdown
# NNNN. タイトル

- 状態：採用 / 置き換え済み（NNNN） / 廃止
- 日付：YYYY-MM-DD

## 背景

なぜ判断が必要になったか。

## 判断

何に決めたか。

## 検討した案

採用しなかった案と、その理由。

## 見直すきっかけ

どうなったらこの判断を見直すか。
```
